# Phase 5 — Sprint 1.1 Hardening

Sprint 1.1 applies the mandatory findings from the Sprint 1 technical review before persistence/MCP work begins.

## Corrections applied

1. **Database-enforced institution isolation**
   - projects must use an identity version from the same institution;
   - project/asset owner must match the private institution owner;
   - active identity must belong to its institution;
   - current asset version must belong to its asset.

2. **SQL enums/checks aligned with the TypeScript domain**
   - project types;
   - project stages;
   - asset types;
   - approval artifact types.

3. **Typed LayoutSpec regions**
   - `header`, `headline`, `hero`, `content`, `footer` are explicit required regions.

4. **Version-bound approvals**
   - state guards compare the currently selected artifact version ID to the exact approved version ID;
   - stale approvals cannot authorize newer artifacts.

5. **Provenance persistence**
   - `provenance_records` stores element origin and enforces generated/documentary/master constraints.

6. **Negative-path hardening tests**
   - generated documentary rejection;
   - documentary photo generated by AI rejection;
   - cross-institution access;
   - owner/institution mismatch;
   - archived master rejection;
   - stale approval rejection;
   - critical-error blocking;
   - 9:16 tolerance.

7. **Migration verification**
   - deterministic migration-contract tests run without infrastructure;
   - a PostgreSQL UP/DOWN/UP integration test is included and activates when `VISUAL4D_TEST_DATABASE_URL` and `psql` are available.

8. **Reproducibility**
   - dependency versions are exact;
   - Node and npm versions are declared;
   - `package-lock.json` is included.

## Important boundary

The v0.1.1 layout solver remains intentionally baseline-only. Candidate generation, collision scoring and editorial optimization belong to Sprint 2; the renderer must not treat the current solver as production-ready.
